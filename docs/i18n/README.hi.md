## यह किस दर्द को हल करता है

हर टीम में वह प्रोजेक्ट होता है जो "बस docker compose से चल जाता है"… और कोई न कोई ठीक उसी कदम पर अटक जाता है।
फ्रंट-एंड डेवलपर, QA, तकनीकी डिज़ाइनर, टीम में नए लोग: जिन्हें रोज़ कंटेनरों की **ज़रूरत** है, पर जो `docker exec -it`, लॉग फ़्लैग या सेवाओं को शुरू करने का सही क्रम याद नहीं रखना चाहते (और उन्हें रखना भी नहीं चाहिए)।

DockDesk इसी दर्शक-वर्ग के लिए है: **जो Docker उपयोग करने वाले प्रोजेक्ट में विकास करते हैं, बिना Docker विशेषज्ञ हुए**। रोज़मर्रा की हर ज़रूरत एक क्लिक पर, स्पष्ट नामों के साथ, छह भाषाओं में, और नीचे क्या हो रहा है यह छिपाए बिना (समकक्ष कमांड इंटरफ़ेस में दिखते हैं)।

## यह क्या करता है

### कंटेनर
- लाइव सूची: स्थिति, **CPU और मेमोरी** उपयोग, पोर्ट मैपिंग और खोज;
- एक क्लिक में **चालू, बंद, पुनः आरंभ और हटाना** (हटाने से पहले पुष्टि);
- कंटेनर **Compose प्रोजेक्ट के अनुसार समूहित** (DockDesk के बाहर शुरू हुए प्रोजेक्ट भी), खुला/बंद स्थिति याद रहती है और **खींचकर क्रम बदलना** संभव;
- विवरण पैनल: इमेज, आंतरिक IP, नेटवर्क, पोर्ट, वॉल्यूम/माउंट और पर्यावरण चर।

### टर्मिनल और कमांड
- **वास्तविक इंटरैक्टिव टर्मिनल** (`docker exec -it` के समान), इमेज में उपलब्ध **shell की स्वचालित पहचान** (bash, zsh, fish, ash, sh…) के साथ;
- **कमांड चलाएँ**: आउटपुट, stderr और एग्ज़िट कोड, टर्मिनल खोले बिना;
- स्मार्ट ऑटो-स्क्रॉल के साथ **लाइव लॉग**;
- टैब बदलने पर चल रहा काम सुरक्षित रहता है, साफ़ करने के बटन के साथ।

### रूटीन (प्रति-कंटेनर शॉर्टकट)
- `htop`, `npm run dev` या `composer install` जैसे बटन बनाएँ;
- **आंशिक रूटीन**: स्थिर कमांड (जैसे `cd /home/project`) चलाते समय पूरक पूछती है (जैसे `&& npm install`);
- **`[--]` मार्कर**: कमांड में `[--]` लिखकर तय करें कि पूरक **कहाँ** जाएगा, सिर्फ़ अंत में नहीं — लिखा गया टेक्स्ट **हर** मार्कर में भरता है (जैसे `cd /app/[--] && npm run [--]`);
- **नाम और कमांड लंबे होने पर अपने आप लाइन तोड़ते हैं**, और आपके Enter से बने लाइन ब्रेक चलाते समय भी बने रहते हैं;
- एडिटर के फ़ील्ड **टेक्स्ट के साथ बढ़ते हैं** और उनमें **रिसाइज़ हैंडल** है: एक बार खींचने पर ऊँचाई वही रहती है जो आपने चुनी;
- हर रूटीन **अपनी पंक्ति से जुड़े अपने टर्मिनल** में चलती है, जब तक प्रक्रिया जीवित है दिखती रहती है (`npm run dev` के लिए आदर्श), **रनिंग संकेतक**, छोटा करने और रोकने के बटन के साथ;
- कंटेनर नाम से सहेजी जाती हैं: कंटेनर दोबारा बनने पर भी बची रहती हैं।

### Compose प्रोजेक्ट
- अपने प्रोजेक्ट का फ़ोल्डर बताएँ और DockDesk **खुद `docker-compose.yml` ढूँढ लेता है** (4 स्तर तक, `node_modules` आदि छोड़कर);
- एक क्लिक में **चालू (`up -d`), बंद और पुनः आरंभ**, रीयल-टाइम आउटपुट कंसोल और चालू सेवाओं की गिनती;
- संदर्भ-सचेत बटन: सब चालू होने पर "चालू करें" गायब; "पुनः आरंभ/बंद करें" केवल तभी दिखते हैं जब कुछ चल रहा हो।

### इमेज, वॉल्यूम और नेटवर्क
- सभी अपने Compose प्रोजेक्ट के अनुसार समूहित, क्रम बदलने योग्य;
- सुरक्षित हटाना (संसाधन उपयोग में होने पर चेतावनी);
- Docker के डिफ़ॉल्ट नेटवर्क चिह्नित और हटाने से सुरक्षित।

### अनुभव
- एक क्लिक में **लाइट/डार्क थीम**;
- **6 भाषाएँ**: Português (BR), English, 中文, हिन्दी, Español और Français, इंटरफ़ेस और ट्रे में;
- **सिस्टम ट्रे**: बंद करने पर ट्रे में छिपता है; सिस्टम के साथ शुरू और छिपा हुआ शुरू के विकल्प;
- **एकल इंस्टेंस**: दोबारा खोलने पर मौजूदा विंडो ही फ़ोकस होती है;
- समूहों का क्रम, थीम, भाषा और खुला/बंद स्थिति सत्रों के बीच बनी रहती है।

## इंस्टॉलेशन

[Releases](https://github.com/vitormoreiradesenvolvedor/dockdesk-linux/releases) से नवीनतम `.AppImage` डाउनलोड करें, निष्पादन अनुमति दें और चलाएँ:

```bash
chmod +x DockDesk-*.AppImage
./DockDesk-*.AppImage
```

**आवश्यकताएँ:** Docker Engine चालू वाला Linux और आपका उपयोगकर्ता `docker` समूह में
(`sudo usermod -aG docker $USER`); प्रोजेक्ट क्षेत्र के लिए Docker Compose v2।

## विकास

```bash
npm install          # प्रोजेक्ट के git हुक्स भी सक्रिय करता है
npm start            # renderer बिल्ड + ऐप खोलता है
npm run test:e2e     # एंड-टू-एंड परीक्षण (Playwright + असली Docker)
npm run dist         # release/ में AppImage बनाता है
```

- **आर्किटेक्चर:** `electron/` (मुख्य प्रक्रिया: dockerode से socket द्वारा Docker, `contextBridge` से एक्सपोज़्ड) · `src/` (React + TypeScript + Vite, टर्मिनल xterm.js) · `tests/e2e/` (Playwright असली ऐप चलाता है)।
- **Git प्रवाह और शासन:** ब्रांच, कमिट, PR नियम और स्वचालित रिलीज़ [docs/git/governanca.hi.md](../git/governanca.hi.md) में।
